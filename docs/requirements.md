# 요구사항 정의

이 문서는 이커머스 주문 흐름의 첫 구현 기준을 정리한다.
구현 중 정책이 변경되면 이 문서를 함께 갱신한다.

## 서비스 컨셉

- 콘텐츠 IP 기반 한정판 굿즈를 판매하는 드롭 커머스 플랫폼으로 시작한다.
- 판매 대상은 웹툰, 웹소설, 영화, 드라마, 음악 등 콘텐츠 IP와 연결된 실물 굿즈다.
- 초기 상품 예시는 오리지널 사운드트랙 한정 LP, 수상비행기 피규어, 작가 드로잉 원화, 마스코트 봉제 인형, 네온 로고 아크릴 키링이다.
- 초기에는 단일 운영자가 상품과 이벤트를 관리한다고 가정한다.
- 파트너사, 창작자, 이벤트 회사가 직접 입점하는 구조는 이후 확장 후보로 둔다.
- 첫 구현에서는 콘텐츠 IP, 이벤트, 파트너사를 별도 도메인으로 분리하지 않고 상품의 설명과 분류 정보로 다룬다.

## 1. 현재 목표

- 장바구니 기반 주문 생성 기능을 구현한다.
- 주문 생성 후 결제 대기 상태를 만들고, 가짜 결제 성공/취소 흐름을 구현한다.
- 주문 과정에서 상품 상태, 재고, 쿠폰 사용 가능 여부를 검증한다.
- 주문 기능 구현 후 분당 100건의 주문 처리 가능 여부를 측정한다.

## 2. 구현 범위

### 백엔드 1차 기능 목록

- 상품 및 재고
- 장바구니
- 주문 생성
- 재고 예약
- 가짜 결제 성공/취소
- 결제 대기 주문 만료 처리
- 고객 보유 쿠폰 사용
- 상품 즉시 할인 적용
- 쿠폰 발급/조회

### 프론트엔드 1차 기능 목록

프론트엔드는 데모 전용 화면이 아니라, 고객이 실제 쇼핑 흐름을 수행할 수 있는 MVP UI로 구현한다.
포트폴리오 설명을 위해 내부 상태를 관찰할 수 있는 보조 기능을 함께 제공한다.

- 상품 목록 조회
- 상품 상세 조회
- 장바구니 담기
- 장바구니 조회, 수량 변경, 삭제
- 발급 가능 쿠폰 조회
- 쿠폰 발급
- 내 보유 쿠폰 조회
- 장바구니 선택 상품 주문 생성
- 주문 목록 조회
- 주문 상세 조회
- 가짜 결제 성공/취소
- 포트폴리오용 상태 관찰 패널

### 프론트엔드 화면 범위

- `/products`: 상품 목록
- `/products/{productId}`: 상품 상세
- `/cart`: 장바구니
- `/coupons`: 쿠폰 발급과 보유 쿠폰 조회
- `/checkout`: 주문 상품 확인, 쿠폰 선택, 주문 생성
- `/orders`: 주문 목록
- `/orders/{orderId}`: 주문 상세, 가짜 결제 성공/취소
- `/report`: 성능 개선 리포트. 성능 측정 전에는 측정 예정 상태를 표시한다.

### 프론트엔드 리팩토링 및 UI 개선 우선순위

현재 프론트엔드는 핵심 화면과 API 연결은 구현되어 있으나, 반응형 레이아웃, 디자인 토큰, 폰트 적용, 페이지 구분감, 쿠폰 화면 구조가 일관되지 않다.
다음 프론트엔드 작업은 신규 화면 추가보다 전체 UI 품질과 실제 쇼핑 흐름 완성도를 우선한다.

1. Tailwind CSS를 도입해 전체 프론트엔드를 리팩토링한다.
2. `DESIGN.md` 기준의 색상, 폰트, 간격, 카드, 버튼, 탭, 패널 스타일을 Tailwind 토큰으로 반영한다.
3. Pretendard 계열 폰트가 실제 UI에 적용되도록 설정한다.
4. `/checkout`의 좁은 화면 레이아웃 겹침을 수정한다.
5. `/coupons`는 발급 가능 쿠폰과 내 보유 쿠폰을 탭 또는 segmented control로 분리한다.
6. 쿠폰 발급 화면의 노란색 계열 강조는 줄이고, `DESIGN.md`의 RIDI Blue는 정보성 강조, 활성 상태, 포커스, 보조 CTA에 사용한다.
7. 주문 생성 성공 후에는 확인 모달에 머무르지 않고 `/orders/{orderId}`로 이동해 바로 결제 성공/취소 액션을 선택할 수 있게 한다.
8. 페이지 본문과 오른쪽 상태 관찰 패널은 배경색, 경계선, 그림자, 여백으로 명확히 구분한다.
9. 네비게이션 로고는 단순 택배 박스보다 한정판 굿즈 느낌이 나는 리본 달린 선물 상자 또는 더 미니멀한 굿즈 상징으로 개선한다.
10. 상품 목록, 상세, 장바구니, 체크아웃, 주문 상세에서 사용할 상품 이미지와 썸네일을 추가한다.

첫 버전 상품 이미지는 프론트엔드에서 상품 ID별 로컬 이미지 자산을 매핑하는 방식으로 제공한다.
이미지 바이너리는 DB에 저장하지 않는다.
향후 실제 상품 이미지 운영이 필요해지면 상품 응답에 `imageUrl` 문자열을 포함하는 방식으로 확장한다.

### 포트폴리오 관찰 기능

일반 사용 흐름을 방해하지 않는 선에서 백엔드 상태 변화를 보여준다.
데스크톱에서는 오른쪽 보조 패널, 모바일에서는 접을 수 있는 패널 또는 별도 탭으로 제공한다.

- 현재 고객 ID
- 최근 API 호출과 응답 상태
- 상품별 현재 재고
- 현재 고객의 장바구니 항목
- 현재 고객의 보유 쿠폰 상태
- 최근 주문 상태
- 결제 대기 주문의 만료 시간

### 데모 데이터

- 포트폴리오 데모 환경에서는 가상 콘텐츠 IP 기반 한정판 굿즈 샘플 데이터를 제공한다.
- 초기 상품 이미지는 상품 ID별 프론트엔드 로컬 이미지 자산으로 표시한다.
- 첫 버전의 데모 상품, 재고, 상품 즉시 할인, 쿠폰 원본은 Flyway 샘플 데이터로 준비한다.
- 초기 상품 예시는 다음을 기준으로 시작한다.
  - `[Sunny Side Up] Original Soundtrack Limited LP`
  - `[Savoia] S-21 수상비행기 피규어`
  - `[구름을 만드는 정비소] 하레 작가 드로잉 원화`
  - `[우주에서 온 묘코] 묘코 마스코트 봉제 인형`
  - `[사이버펑크 2088] 네온 로고 아크릴 키링`
- 쿠폰 원본 생성 UI는 1차 프론트엔드 범위에 포함하지 않는다.
- 데모용 쿠폰 원본은 샘플 데이터로 준비한다.

### 관리자 기능

- 첫 버전에서는 관리자 계정, 관리자 인증/인가, 관리자 화면을 구현하지 않는다.
- 상품 등록, 상품 수정, 상품 판매 상태 변경, 재고 변경 API는 운영자용 API라는 전제만 둔다.
- 쿠폰 원본 등록, 수정, 비활성화 API와 관리자 UI는 1차 범위에 포함하지 않는다.
- 관리자 계정, 상품 등록 화면, 쿠폰 원본 등록 화면은 이후 구현 예정 기능으로 둔다.

### 이후 구현 예정

- 인증/인가
- 관리자 계정과 관리자 인증/인가
- 관리자 상품 등록/수정 화면
- 관리자 쿠폰 원본 등록/수정 화면
- 실제 결제 API 연동
- 콘텐츠 IP 및 이벤트 관리
- 파트너사 또는 창작자 입점 관리
- 배송 기능
- 주문 완료 후 취소/반품
- 바로 구매
- 가격 변경 이력 관리

## 3. 고객과 인증

- 첫 버전에서는 인증/인가를 구현하지 않는다.
- API 요청에서 `customerId`를 받아 고객을 식별한다.
- 장바구니, 주문, 쿠폰은 `customerId` 기준으로 소유자를 구분한다.
- 이후 인증/인가 도입 시 요청 값의 `customerId` 대신 인증된 사용자 정보를 사용한다.

## 4. 상품과 재고

### 상품 상태

- 상품 상태는 `ON_SALE`, `STOPPED`로 시작한다.
- `ON_SALE` 상태의 상품만 주문할 수 있다.
- 품절은 별도 상품 상태로 관리하지 않고 재고 수량으로 판단한다.

### 재고 정책

- 주문 생성 시점에 상품 재고를 검증한다.
- 현재 재고가 주문 수량 이상이면 주문할 수 있다.
- 주문 완료 후 재고가 0이 되는 것은 허용한다.
- 현재 재고가 주문 수량보다 적으면 주문할 수 없다.
- 주문 생성이 성공하면 결제 대기 상태에서도 재고를 즉시 차감한다.
- 결제 취소 또는 결제 대기 만료 시 차감했던 재고를 복구한다.

## 5. 장바구니

- 고객은 상품을 장바구니에 담을 수 있다.
- 고객당 같은 상품은 장바구니에 한 줄만 존재한다.
- 같은 상품을 다시 담으면 기존 장바구니 수량이 증가한다.
- 장바구니 수량은 현재 재고보다 크게 변경할 수 없다.
- 장바구니 상품 추가 또는 수량 변경 후 최종 수량이 현재 재고보다 크면 실패한다.
- 장바구니 상품 수정과 삭제는 요청 고객의 장바구니에 속한 상품에만 허용한다.
- 장바구니 조회 시 상품의 현재 판매 상태와 재고 상태를 함께 보여준다.
- 장바구니 조회 시 활성 상품 즉시 할인 금액과 할인 후 단가를 함께 보여준다.
- 판매 중지 상품이나 재고 부족 상품은 장바구니에 표시하되 주문 선택은 불가능하다.
- 사용자는 장바구니에서 주문할 상품을 선택할 수 있다.
- 전체 선택을 통해 장바구니의 주문 가능 상품 전체를 주문할 수 있다.
- 백엔드는 주문 생성 시점에 상품 상태와 재고를 다시 검증한다.

## 6. 주문

### 주문 생성

- 주문은 장바구니에서 선택한 상품을 기준으로 생성한다.
- 주문 상품마다 수량을 가진다.
- 주문 생성 시 상품 상태, 재고, 쿠폰 사용 가능 여부를 검증한다.
- 주문은 전체 성공 또는 전체 실패로 처리한다.
- 일부 상품 또는 쿠폰 검증이 실패하면 주문 전체를 실패시킨다.
- 주문 생성 실패 시 재고 차감, 쿠폰 예약, 주문 저장 등 어떤 변경도 남기지 않는다.
- 주문 생성 성공 시 주문 상태는 `PAYMENT_PENDING`이 된다.
- 주문 생성 성공 시 선택 상품의 재고를 즉시 차감한다.
- 주문 생성 성공 시 고객 보유 쿠폰은 `RESERVED` 상태로 예약한다.
- 고객 보유 쿠폰은 결제 성공 시 `USED`, 결제 취소 또는 결제 대기 만료 시 `AVAILABLE`로 전이된다.

### 주문 상태

- `PAYMENT_PENDING`: 결제 대기
- `COMPLETED`: 주문 완료
- `CANCELED`: 주문 취소

### 주문 취소 사유

- `PAYMENT_CANCELED`: 사용자가 결제를 취소함
- `PAYMENT_EXPIRED`: 결제 대기 시간이 만료됨

### 주문 금액 저장

주문에는 주문 당시 금액 정보를 저장한다.

- 상품 원금액 합계
- 상품 즉시 할인 금액 합계
- 고객 보유 쿠폰 할인 금액 합계
- 최종 결제 금액

주문 상품 라인에는 주문 당시 상품 정보를 저장한다.

- 상품 주문 당시 가격
- 주문 수량
- 상품 원금액
- 상품 즉시 할인 금액
- 특정 상품 쿠폰 할인 금액
- 라인 최종 금액

## 7. 가짜 결제

- 실제 결제 API는 이후 연동한다.
- 첫 버전에서는 가짜 결제 성공/취소 API로 결제 흐름을 구현한다.
- 결제 금액이 0원이어도 가짜 결제 성공 API를 호출해 동일한 상태 흐름을 따른다.

### 결제 성공

- 결제 성공 API는 `PAYMENT_PENDING` 주문에만 호출할 수 있다.
- 결제 성공 시 결제 대기 만료 여부를 검증한다.
- 결제 대기 시간이 지나지 않았다면 주문 상태를 `COMPLETED`로 변경한다.
- 결제 성공 시 예약된 고객 보유 쿠폰을 `USED` 상태로 변경한다.
- 결제 성공 시 주문한 장바구니 상품을 장바구니에서 제거한다.
- 결제 성공 시 장바구니 제거는 주문 생성에 사용된 장바구니 상품 ID를 기준으로 처리한다.
- 주문 생성 후 사용자가 같은 상품을 장바구니에 다시 담은 경우 새 장바구니 상품은 제거하지 않는다.
- 주문 생성 후 같은 장바구니 상품의 수량이 증가한 경우 결제 성공 시 주문 수량만큼만 차감하고 남은 수량은 유지한다.

### 결제 취소

- 결제 취소 API는 `PAYMENT_PENDING` 주문에만 호출할 수 있다.
- 결제 취소 시 주문 상태를 `CANCELED`로 변경한다.
- 결제 취소 사유는 `PAYMENT_CANCELED`로 기록한다.
- 결제 취소 시 차감했던 재고를 복구한다.
- 결제 취소 시 예약된 고객 보유 쿠폰을 `AVAILABLE` 상태로 되돌린다.
- `COMPLETED` 주문의 취소/반품은 첫 구현 범위에서 제외한다.

## 8. 결제 대기 만료

- 결제 대기 주문의 유효 시간은 10분이다.
- 스케줄러는 1분마다 만료된 `PAYMENT_PENDING` 주문을 찾는다.
- 결제 대기 시간이 10분을 초과한 주문은 `CANCELED` 상태로 변경한다.
- 만료 취소 사유는 `PAYMENT_EXPIRED`로 기록한다.
- 만료 처리 시 차감했던 재고를 복구한다.
- 만료 처리 시 예약된 고객 보유 쿠폰을 `AVAILABLE` 상태로 되돌린다.
- 결제 성공 API에서도 만료 여부를 한 번 더 검증한다.
- 만료된 주문에 결제 성공 API가 호출되면 주문을 취소 처리하고 실패 응답을 반환한다.

## 9. 쿠폰과 할인

### 쿠폰 종류

고객 보유 쿠폰은 고객이 발급받고 주문 시 직접 사용하는 쿠폰이다.

- 전체 상품 쿠폰: 주문 전체 금액에 1회 적용한다.
- 특정 상품 쿠폰: 특정 상품 1개에 적용한다.
- 첫 주문 쿠폰은 현재 데모 데이터와 쿠폰 API 범위에서 제외한다.
- 첫 주문 쿠폰은 이후 인증/인가와 회원가입 기능 구현 후, 회원가입 시 고객당 1개 자동 발급되는 정책으로 별도 구현한다.

상품 즉시 할인은 상품에 설정된 자동 할인이다.

- 고객이 직접 발급받지 않는다.
- 고객 쿠폰 발급/사용 이력을 남기지 않는다.
- 주문 할인 내역에는 즉시 할인 금액을 저장한다.
- 상품당 최대 1개의 즉시 할인 정책만 적용한다.
- 활성 상태이고 적용 기간에 포함되는 상품 즉시 할인만 주문에 적용한다.
- 상품 즉시 할인은 상품 1개당 할인 금액으로 적용하고, 주문 수량만큼 합산한다.
- 상품 1개당 즉시 할인 금액은 상품 가격을 초과할 수 없으며, 초과하는 경우 상품 가격까지만 적용한다.

### 고객 보유 쿠폰 사용 규칙

- 쿠폰이 없어도 주문할 수 있다.
- 한 주문에는 전체 상품 쿠폰을 최대 1개 사용할 수 있다.
- 한 주문에는 상품별로 특정 상품 쿠폰을 최대 1개씩 사용할 수 있다.
- 같은 고객 보유 쿠폰은 한 주문에 중복 사용할 수 없다.
- 전체 상품 쿠폰과 특정 상품 쿠폰은 함께 사용할 수 있다.
- 고객 보유 쿠폰과 상품 즉시 할인은 함께 적용할 수 있다.
- 특정 상품 쿠폰은 주문에 해당 상품이 여러 개 있어도 상품 1개에만 할인된다.
- 특정 상품 쿠폰은 상품 즉시 할인 적용 후 남은 상품 1개 금액까지만 할인된다.
- 전체 상품 쿠폰은 주문 전체 금액에 1회 적용된다.

### 쿠폰 상태

- `AVAILABLE`: 사용 가능
- `RESERVED`: 결제 대기 주문에 예약됨
- `USED`: 사용 완료
- `EXPIRED`: 만료됨

### 쿠폰 검증 조건

주문 생성 시 고객 보유 쿠폰은 아래 조건을 모두 만족해야 한다.

- 주문 고객이 보유한 쿠폰이다.
- 쿠폰 상태가 `AVAILABLE`이다.
- 쿠폰 만료 시간이 지나지 않았다.
- 쿠폰 타입과 적용 대상이 주문 상품과 일치한다.
- 할인 금액이 0보다 크다.

주문 생성 시점에 유효해 `RESERVED` 처리된 쿠폰은 결제 대기 시간 안에서는 만료 시간이 지나도 해당 주문에 사용할 수 있다.
결제 대기 시간이 만료되면 주문이 취소되고 쿠폰 예약도 해제된다.

### 만료 쿠폰

- 만료된 쿠폰은 사용할 수 없다.
- 만료된 쿠폰은 삭제하지 않는다.
- 발급 가능 쿠폰 조회에서는 만료된 쿠폰 원본을 제외한다.
- 내 보유 쿠폰 조회에서는 `AVAILABLE` 상태인 쿠폰 원본이 만료된 경우 응답 상태를 `EXPIRED`로 표시한다.
- 첫 구현에서는 만료 상태를 DB에 자동 갱신하지 않고 조회 시점에 계산한다.

### 쿠폰 발급

- 이벤트 페이지의 쿠폰 발급 버튼을 통해 고객 보유 쿠폰을 발급할 수 있다.
- 고객은 같은 쿠폰 원본을 1번만 발급받을 수 있다.
- 이미 발급받은 쿠폰 발급 요청은 `COUPON_ALREADY_ISSUED`로 실패한다.

## 10. 금액 계산 순서

할인 방식은 정액 할인부터 시작한다.
할인 적용 후 금액은 0원 미만이 될 수 없다.

상품별 금액 계산 순서는 다음과 같다.

```text
상품 원금액
- 상품 즉시 할인
- 특정 상품 쿠폰 할인
= 상품별 할인 후 금액
```

주문 전체 금액 계산 순서는 다음과 같다.

```text
상품별 할인 후 금액 합계
- 전체 상품 쿠폰 할인
= 최종 결제 금액
```

## 11. 실패 처리

### 주문 생성 실패

아래 상황에서는 주문 전체를 실패시킨다.

- 판매 중이 아닌 상품이 포함됨
- 재고가 부족한 상품이 포함됨
- 고객이 보유하지 않은 쿠폰 사용 요청
- 이미 사용된 쿠폰 사용 요청
- 만료된 쿠폰 사용 요청
- 예약 중인 쿠폰 사용 요청
- 쿠폰 타입 또는 적용 대상이 주문과 일치하지 않음

주문 생성 실패 응답에는 가능한 경우 아래 정보를 포함한다.

- 실패 상품 ID
- 실패 쿠폰 ID
- 실패 사유 코드
- 사용자 메시지
- 현재 재고

### 실패 사유 코드

초기 실패 사유 코드는 다음을 기준으로 시작한다.

- `PRODUCT_NOT_ON_SALE`
- `OUT_OF_STOCK`
- `CART_ITEM_NOT_FOUND`
- `CART_ITEM_NOT_SELECTABLE`
- `COUPON_NOT_FOUND`
- `COUPON_NOT_OWNED`
- `COUPON_NOT_AVAILABLE`
- `COUPON_ALREADY_ISSUED`
- `COUPON_ALREADY_USED`
- `COUPON_RESERVED`
- `COUPON_EXPIRED`
- `COUPON_TARGET_MISMATCH`
- `ORDER_NOT_PAYMENT_PENDING`
- `ORDER_PAYMENT_EXPIRED`
