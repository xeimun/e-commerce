# 도메인 모델

이 문서는 클래스와 테이블의 최종 명세가 아니라, 도메인 개념과 책임을 정리하는 문서다.
속성과 메서드는 구현 과정에서 변경될 수 있으므로 핵심 정보와 관계 중심으로 기록한다.
실제 필드 변경을 모두 따라가지 않고, 중요한 도메인 변경이 있을 때 갱신한다.

## 서비스 도메인 방향

- 이 서비스는 콘텐츠 IP 기반 한정판 굿즈를 판매하는 드롭 커머스 플랫폼이다.
- 첫 구현에서는 콘텐츠 IP, 이벤트, 파트너사를 별도 도메인으로 분리하지 않는다.
- 상품, 재고, 장바구니, 주문, 결제 대기, 쿠폰 흐름을 먼저 구현한다.
- 콘텐츠 IP 및 이벤트 관리는 이후 확장 시 별도 도메인으로 분리할 수 있다.

## 도메인 목록

- Customer
- Product
- Stock
- Cart
- CartItem
- Order
- OrderItem
- Payment
- Coupon
- IssuedCoupon
- ProductDiscount

## Customer

### 책임

- 서비스를 이용하는 고객을 표현한다.
- 장바구니, 주문, 발급 쿠폰의 소유자를 구분하는 기준이 된다.
- 첫 버전에서는 인증/인가를 구현하지 않고 요청의 `customerId`와 연결된다.

### 핵심 정보

- 고객 식별 정보
- 고객 이름 또는 표시 정보
- 첫 구현에서는 별도 Customer 테이블 없이 API 요청의 `X-Customer-Id` 값을 소유자 식별자로 사용한다.

### 주요 관계

- 하나의 Customer는 하나의 Cart를 가진다.
- 하나의 Customer는 여러 Order를 가질 수 있다.
- 하나의 Customer는 여러 IssuedCoupon을 가질 수 있다.

## Product

### 책임

- 콘텐츠 IP 기반 한정판 굿즈의 기본 정보와 판매 상태를 관리한다.
- 주문 가능 여부를 판단할 때 판매 상태를 제공한다.
- 재고와 상품 즉시 할인은 별도 도메인과 연결된다.

### 핵심 정보

- 상품명
- 상품 가격
- 판매 상태
- 콘텐츠명
- 콘텐츠 유형(웹툰, 웹소설, 영화, 드라마, 음악 등)
- 상품 분류
- 상품 설명

### 주요 관계

- 하나의 Product는 하나의 Stock과 연결된다.
- 하나의 Product는 0개 또는 1개의 ProductDiscount와 연결될 수 있다.
- 하나의 Product는 여러 CartItem, OrderItem의 대상이 될 수 있다.

## Stock

### 책임

- 상품 재고를 관리한다.
- 주문 생성 시 재고를 예약 차감한다.
- 결제 취소 또는 결제 대기 만료 시 재고를 복구한다.
- 재고 부족 여부를 판단한다.

### 핵심 정보

- 대상 상품
- 현재 재고 수량

### 주요 관계

- 하나의 Stock은 하나의 Product와 1:1로 연결된다.

## Cart

### 책임

- 고객의 장바구니를 표현한다.
- 고객이 주문할 상품 후보를 담는 컨테이너 역할을 한다.

### 핵심 정보

- 장바구니 소유 고객 ID
- 장바구니 상품 목록

### 주요 관계

- 하나의 Cart는 하나의 Customer와 연결된다.
- 하나의 Cart는 여러 CartItem을 가진다.

## CartItem

### 책임

- 장바구니에 담긴 상품 한 줄을 표현한다.
- 같은 고객 장바구니 안에서 같은 상품은 한 줄만 존재한다.
- 장바구니 수량이 현재 재고를 초과하지 않도록 관리한다.
- 주문 가능 여부를 표시할 때 상품 상태와 재고 상태를 함께 사용한다.
- 요청 고객의 장바구니에 속한 상품만 수정하거나 삭제할 수 있다.

### 핵심 정보

- 대상 장바구니
- 대상 상품
- 장바구니 수량
- 주문 선택 가능 여부
- 주문 선택 불가 사유

### 주요 관계

- 하나의 CartItem은 하나의 Cart에 속한다.
- 하나의 CartItem은 하나의 Product를 가리킨다.

## Order

### 책임

- 장바구니에서 선택한 상품으로 생성된 주문을 표현한다.
- 결제 대기, 완료, 취소 상태를 관리한다.
- 결제 대기 만료 시간을 가진다.
- 주문 전체 금액과 할인 금액의 스냅샷을 가진다.
- 결제 취소 또는 만료 시 재고 복구와 쿠폰 예약 해제를 위한 기준이 된다.

### 핵심 정보

- 주문 고객
- 주문 상태
- 주문 상품 목록
- 주문 금액
- 결제 대기 만료 시간
- 취소 사유
- 첫 주문 생성 단계에서는 상품 즉시 할인과 쿠폰 할인 금액을 0으로 저장한다.

### 주요 관계

- 하나의 Order는 하나의 Customer와 연결된다.
- 하나의 Order는 여러 OrderItem을 가진다.
- 하나의 Order는 하나의 Payment와 연결된다.
- 하나의 Order는 예약 또는 사용된 IssuedCoupon과 연결될 수 있다.

## OrderItem

### 책임

- 주문에 포함된 상품 한 줄을 표현한다.
- 주문 당시 상품 정보와 금액을 보존한다.
- 상품별 즉시 할인과 특정 상품 쿠폰 할인 결과를 보존한다.

### 핵심 정보

- 대상 주문
- 대상 상품
- 주문 당시 상품명
- 주문 당시 상품 가격
- 주문 수량
- 상품별 원금액
- 상품별 할인 금액
- 상품별 최종 금액
- 첫 주문 생성 단계에서는 주문 당시 상품 가격과 수량으로 원금액과 최종 금액을 계산한다.

### 주요 관계

- 하나의 OrderItem은 하나의 Order에 속한다.
- 하나의 OrderItem은 하나의 Product를 참조할 수 있다.

## Payment

### 책임

- 주문의 결제 흐름을 표현한다.
- 첫 버전에서는 실제 결제 API 대신 가짜 결제 성공/취소 흐름을 관리한다.
- 이후 실제 결제 API 연동 시 외부 결제 결과와 주문 상태를 연결하는 역할로 확장될 수 있다.

### 핵심 정보

- 대상 주문
- 결제 금액
- 결제 상태
- 결제 성공 시각
- 결제 취소 시각

### 주요 관계

- 하나의 Payment는 하나의 Order와 연결된다.

## Coupon

### 책임

- 고객에게 발급될 수 있는 쿠폰 정책 원본을 표현한다.
- 쿠폰의 할인 금액, 적용 범위, 만료 조건을 관리한다.
- 실제 고객의 보유/사용 상태는 IssuedCoupon이 관리한다.

### 핵심 정보

- 쿠폰명
- 쿠폰 타입
- 할인 금액
- 적용 대상
- 만료 시간

### 주요 관계

- 하나의 Coupon은 여러 IssuedCoupon의 원본이 될 수 있다.
- 특정 상품 쿠폰은 Product와 연결될 수 있다.

## IssuedCoupon

### 책임

- 고객에게 발급된 쿠폰을 표현한다.
- 고객 보유 쿠폰의 사용 가능, 예약, 사용 완료, 만료 상태를 관리한다.
- 주문 생성 시 결제 대기 주문에 예약되고, 결제 성공 시 사용 완료 처리된다.
- 결제 취소 또는 만료 시 사용 가능 상태로 복구된다.

### 핵심 정보

- 원본 쿠폰
- 보유 고객
- 연결 주문
- 쿠폰 상태
- 발급 시각
- 예약 시각
- 사용 시각

### 주요 관계

- 하나의 IssuedCoupon은 하나의 Coupon을 원본으로 가진다.
- 하나의 IssuedCoupon은 하나의 Customer에 속한다.
- 하나의 IssuedCoupon은 예약 또는 사용 시 하나의 Order와 연결될 수 있다.

## ProductDiscount

### 책임

- 상품에 자동 적용되는 즉시 할인 정책을 표현한다.
- 고객 발급/사용 이력 없이 주문 시 자동으로 할인된다.
- 주문 할인 내역에는 적용된 즉시 할인 금액이 저장된다.

### 핵심 정보

- 대상 상품
- 할인명
- 할인 금액
- 적용 시작 시간
- 적용 종료 시간
- 활성 여부

### 주요 관계

- 하나의 ProductDiscount는 하나의 Product와 연결된다.
- 하나의 Product에는 최대 1개의 활성 ProductDiscount만 적용한다.
