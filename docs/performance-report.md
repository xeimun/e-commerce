# 성능 측정 및 개선 기록

이 문서는 기준 성능 측정, 병목 가설, 개선 내용, 재측정 결과를 정리한다.
아직 성능 측정 단계에 들어가지 않은 항목은 향후 측정 후보로만 기록한다.

## 향후 측정 후보

### 장바구니 상품 추가 동시성 정합성

#### 배경

장바구니에 이미 같은 상품이 있는 상태에서 `POST /api/v1/cart/items` 요청이 동시에 들어오면, 현재 구현의 읽기-계산-쓰기 흐름에서 lost update가 발생할 수 있다.
예를 들어 기존 수량이 1이고 동시에 1개 추가 요청 2건이 들어오면 기대 수량은 3이지만, 두 트랜잭션이 같은 기존 수량을 읽으면 최종 수량이 2로 남을 수 있다.

#### 측정 가치

- 더블 클릭, 모바일 재시도, 클라이언트 중복 요청 같은 일반적인 상황에서 수량 증가 규칙이 유지되는지 확인할 수 있다.
- 단순 평균 응답 시간보다 동시성 환경에서의 정합성 실패율을 함께 측정할 수 있다.
- 이후 주문 생성과 재고 차감 동시성 테스트를 설계하기 위한 작은 선행 사례로 활용할 수 있다.

#### 측정 아이디어

- 기준 상태: 고객 1명의 장바구니에 특정 상품 수량 1개가 이미 담겨 있음
- 부하 조건: 같은 고객, 같은 상품으로 `POST /api/v1/cart/items` 추가 요청을 동시에 N건 전송
- 기대 결과: 최종 장바구니 수량이 `기존 수량 + 성공 요청 수량 합계`와 일치
- 관찰 지표: 최종 수량 정합성, 실패율, 응답 시간, 처리량, DB 락 대기 또는 충돌 발생 여부

#### 개선 후보

- 대상 `cart_items` 행에 비관적 락 적용
- JPA `@Version` 기반 낙관적 락 적용
- DB의 원자적 수량 증가 쿼리 사용

#### 현재 상태

- 아직 개선을 적용하지 않는다.
- 장바구니 기능 PR의 코드 리뷰에서 발견된 향후 측정 및 개선 후보로 보관한다.
